## 🗄️ Работа с проектом, Git и миграциями (uv + Flask-Migrate)

В проекте используется менеджер пакетов **uv** для управления зависимостями и окружением, а также **Flask-Migrate** для контроля структуры базы данных SQLite. Настройки безопасности вынесены в переменные окружения через **python-dotenv**.

---

### 🚀 1. Первый запуск проекта (на новом компьютере)

Если вы только склонировали репозиторий, папка `migrations/` уже есть в проекте. Чтобы поднять окружение, настроить секреты и создать локальную базу данных:

1. Склонируйте репозиторий и перейдите в папку проекта:
   ```bash
   git clone <ссылка_на_репозиторий>
   cd <название_папки>
   ```
2. Установите зависимости и создайте виртуальное окружение с помощью `uv`:
   ```bash
   uv sync
   ```
3. Создайте в корне проекта файл **`.env`** (он находится в `.gitignore` и не попадет в репозиторий). Добавьте в него локальные настройки:
   ```text
   SECRET_KEY=93d0bcf0bce0df9d694c958566690c66df71b8ffbb3aa591ce87c0df099275d5
   SQLALCHEMY_DATABASE_URI=sqlite:///app.db
   FLASK_DEBUG=True
   ```
4. Задайте переменную окружения Flask для указания главного файла (в зависимости от вашего терминала):
   * **Linux/macOS:** `export FLASK_APP=main.py`
   * **Windows (cmd):** `set FLASK_APP=main.py`
   * **Windows (PowerShell):** `$env:FLASK_APP="main.py"`
5. Создайте локальную БД и примените актуальную структуру:
   ```bash
   uv run flask db upgrade
   ```
   *После этого автоматически создастся локальный файл базы данных `app.db`, полностью готовый к работе.*

---

### 🛠️ 2. Как изменить модели (добавить таблицы / поля)

Если вам нужно изменить структуру БД (например, добавить новое поле или создать таблицу):

1. Внесите изменения в код ваших моделей SQLAlchemy в пакете `core/`.
2. Сгенерируйте новый файл миграции с описанием изменений:
   ```bash
   uv run flask db migrate -m "описание изменений (например: add user phone)"
   ```
3. Примените изменения к вашей локальной базе данных:
   ```bash
   uv run flask db upgrade
   ```
4. Проверьте работу приложения локально, запустив сервер: `uv run python main.py`.

---

### 📤 3. Как закомитить изменения в Git

После того как вы изменили код, добавили новые зависимости через `uv add` или создали миграции базы данных, отправьте изменения в репозиторий:

1. Посмотрите список измененных файлов:
   ```bash
   git status
   ```
   *Убедитесь, что в списке нет файла `app.db` и `.env` — они должны игнорироваться.*
2. Добавьте файлы в индекс для коммита:
   ```bash
   git add .
   ```
3. Создайте коммит с понятным описанием:
   ```bash
   git commit -m "feat: добавил модель профиля и настроил python-dotenv"
   ```
4. Отправьте изменения в удаленный репозиторий:
   ```bash
   git push origin master
   ```

---

### 📥 4. Как обновить проект из Git (другому разработчику)

Чтобы получить актуальную версию проекта, которую написал ваш коллега, выполните цепочку команд:

1. Подтяните свежие изменения из удаленного репозитория:
   ```bash
   git pull origin master
   ```
2. Обновите зависимости (если коллега добавил новые библиотеки, `uv` автоматически синхронизирует окружение согласно `uv.lock`):
   ```bash
   uv sync
   ```
3. Примените новые миграции к вашей локальной базе данных:
   ```bash
   uv run flask db upgrade
   ```
   *Ваш локальный файл SQLite обновится до актуальной версии без потери ваших текущих данных.*

---

### ⚠️ Важные правила
* **Никогда не добавляйте файлы `.db`, `.sqlite` и `.env` в Git.** Они должны быть прописаны в `.gitignore`. У каждого разработчика они свои.
* **Не удаляйте папку `migrations/`.** В ней хранится вся история изменений структуры проекта.
* **Всегда фиксируйте `uv.lock` и `pyproject.toml` в Git.** Это гарантирует одинаковые версии библиотек у всех разработчиков.
* Если нужно откатить последнюю примененную миграцию назад, используйте команду `uv run flask db downgrade`.
